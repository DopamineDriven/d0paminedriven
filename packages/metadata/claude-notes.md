End markers include \t?\r?\n\f?\n? — matches bare line endings in decompressed ObjStm content                                                                                                                                                                       
                                                                                                                                                                                                                                                                        
 Why This Matters                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                        
 ChatGPT PDFs (non-linearized v1.7) store ALL objects inside ObjStm (compressed object streams). After decompression via parseObjectStreams(), the content looks like:                                                                                                  
                                                                                                                                                                                                                                                                        
 /Border[0 0 0]/F 4/Rect[78 702.621094 179.25 690.363281]/Subtype/Link/Type/Annot/A<</Type/Action/S/URI/URI(https://chatgpt.com/...)>>                                                                                                                                  
                                                                                                                                                                                                                                                                        
 No \d+ \d+ obj prefix. The psObjRegex can't match this. The old broader regex CAN match it via the optional group 1 and << anchor.                                                                                                                                     
                                                                                                                                                                                                                                                                        
 This means:                                                                                                                                                                                                                                                            
 - examineArr in the new mapper has 19 entries (only raw text objects) vs 304 (including decompressed ObjStm content)                                                                                                                                                   
 - examineToParse is missing all ObjStm data                                                                                                                                                                                                                            
 - /Kids [...] matching finds 0 page IDs → pageIdsMap empty                                                                                                                                                                                                             
 - /Annots [...] matching finds 0 annotation refs → annotIdsMap empty                                                                                                                                                                                                   
 - Page fallback finds 0 pages (no pageIdsMap entries to assign IDs)                                                                                                                                                                                                    
 - Annot fallback finds 0 annotations (no entries in annotsMap since examineArr has no /Annot matches)                                                                                                                                                                  
                                                                                                                                                                                                                                                                        
 The Fix                                                                                                                                                                                                                                                                
                                                                                                                                                                                                                                                                        
 Option A: Restore the old examine regex in mapper/index.ts                                                                                                                                                                                                             
                                                                                                                                                                                                                                                                        
 Replace psObjRegex usage at line 76 with the old broader regex. This is the simplest fix — the old regex was specifically designed to handle ObjStm decompressed content without object headers.                                                                       
                                                                                                                                                                                                                                                                        
 Change in mapper/index.ts line 76:                                                                                                                                                                                                                                     
 // FROM:                                                                                                                                                                                                                                                               
 for (const d of fullText.matchAll(this.psObjRegex)) {                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                        
 // TO:                                                                                                                                                                                                                                                                 
 for (const d of fullText.matchAll(this.examineRe)) {                                                                                                                                                                                                                   
                                                                                                                                                                                                                                                                        
 Where examineRe is the old broader regex (either as a new private field, or inline).                                                                                                                                                                                   
                                                                                                                                                                                                                                                                        
 Pros: Minimal change, proven to work across all 68 PDFs                                                                                                                                                                                                                
 Cons: The broader regex matches more than needed; some matches may be noise                                                                                                                                                                                            
                                                                                                                                                                                                                                                                        
 Option B: Dual-pass examine — strict first, broad fallback                                                                                                                                                                                                             
                                                                                                                                                                                                                                                                        
 Use psObjRegex first (faster, more precise), then if examineArr is too small relative to countFallback, fall back to the broad regex.                                                                                                                                  
                                                                                                                                                                                                                                                                        
 Pros: Best of both worlds — precise when possible, broad when needed                                                                                                                                                                                                   
 Cons: More complex, two regex passes                                                                                                                                                                                                                                   
                                                                                                                                                                                                                                                                        
 Option C: Fix parseObjectStreams() to emit proper object headers                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                        
 Make the ObjStm decompression emit content with synthetic \d+ \d+ obj headers by using the index table that ObjStm provides (object number + offset pairs before firstOffset).                                                                                         
                                                                                                                                                                                                                                                                        
 Pros: Fixes the root cause — downstream regexes all work unchanged                                                                                                                                                                                                     
 Cons: Requires modifying parseObjectStreams() in pdf-workup.ts, which is the base class. The index table parsing needs to be robust.                                                                                                                                   
                                                                                                                                                                                                                                                                        
 My Recommendation                                                                                                                                                                                                                                                      
                                                                                                                                                                                                                                                                        
 Option A first (restore old examine regex), then Option C later as an optimization. Option A is a one-line change that we know works. Option C is the architecturally correct solution but requires careful work on the ObjStm decompressor.                           
                                                                                                                                                                                                                                                                        
 Secondary Issues (from earlier analysis, still relevant)                                                                                                                                                                                                               
                                                                                                                                                                                                                                                                        
 1. Annotation ID mismatch from annots regex (Geminastics-Pt-III case)                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                        
 Even with examineArr fixed, Chromium PDFs with ObjStm-stored annotations still have the ID mismatch issue. The annots regex captures garbage IDs like "220 4294" instead of "207 0".                                                                                   
                                                                                                                                                                                                                                                                        
 The old code handles this via the annotsMap → annotIdsMap reassignment loop (lines 187-200 in mapper). When the annots regex finds garbage IDs but aObjArr.length === 0 (because the annotations were in examineArr instead), the fallback uses annotIdsMap IDs.       
                                                                                                                                                                                                                                                                        
 But when aObjArr.length > 0 (annots regex DID find something, just with wrong IDs), the fallback doesn't fire. This is the Geminastics-Pt-III case.                                                                                                                    
                                                                                                                                                                                                                                                                        
 Fix: In the annotsMap fallback (mapper line 175), change the condition from aObjArr.length === 0 to also check if the IDs in aObjArr match any IDs in annotIdsMap. If they don't match, the aObjArr entries have garbage IDs and should be rebuilt from annotsMap.
